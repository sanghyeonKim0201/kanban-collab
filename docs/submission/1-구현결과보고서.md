- **프로젝트**: TaskFlow — 실시간 칸반 협업 도구

- **개발 도구**: Next.js 14, Supabase(데이터베이스·로그인·실시간), GitHub Webhook, AI(LLM·음성인식)

## 1. 무엇을 만들었나

여러 명이 같이 쓰는 칸반 보드를 만들었다. 카드를 드래그해서 옮기면 다른 사람 화면에도 바로 반영되고, AI가 카드를 자동으로 분류해 주고, GitHub의 PR이 머지되면 카드가 알아서 옮겨진다. 회의 내용을 넣으면 AI가 요약하고 할 일까지 뽑아 준다.

명세서의 기능 요구사항(FR) 27개를 거의 다 구현했고(2개는 일부만), 핵심 4가지 기능 — **AI 자동 분류 · 실시간 협업 · GitHub 연동 · AI 회의록** — 은 실제로 동작한다. 아래 스크린샷은 전부 실제로 돌려서 찍은 화면이다.

### 일부만 한 것 (이유)

- **FR-02 컬럼 순서변경**: 순서를 바꾸는 기능 자체(서버 코드·정렬 값)는 만들었는데, 컬럼을 드래그하는 화면 부분을 카드 드래그와 합치는 걸 시간이 부족해 못 붙였다. 컬럼 추가·수정·삭제·이름변경은 다 된다.
- **FR-26 OAuth 로그인**: 구글·깃허브 로그인 버튼과 코드는 다 있는데, 로컬 환경 주소를 구글/깃허브 쪽에 등록을 안 해서 데모에서는 이메일 로그인을 쓴다. 주소만 등록하면 바로 된다.

## 4. 핵심 기능 설명

### 4-1. 로그인 (FR-26)
이메일로 로그인하면 Supabase가 비밀번호를 안전하게(bcrypt) 저장하고 로그인 토큰(JWT)을 준다. 로그인 안 한 사람은 자동으로 로그인 화면으로 보낸다.

![로그인](../screenshots/01-login.png)

- 코드: `src/middleware.ts`, `src/features/auth-sign-in/ui/auth-form.tsx`

### 4-2. 칸반 보드 · 실시간 협업 (FR-01~13)
3개 칸(In Progress / To Do / Done)에서 카드를 드래그해서 옮긴다. 옮기면 화면에 먼저 반영하고, 만약 다른 사람과 겹치면 되돌린다. 왼쪽에는 진행률, 칸별 개수, PR 자동화 설정, 활동 기록이 보인다. 활동 기록의 `🤖 PR #3 머지됨 → 'API 연동 작업'을 Done으로 이동`은 GitHub가 실제로 카드를 옮긴 흔적이다.

![보드](../screenshots/02-board.png)

- 코드: `entities/board/model/use-board-realtime.ts`, `entities/board/model/store.ts`, `shared/lib/lexorank.ts`

> 실시간 커서·접속자(FR-10·12)는 다른 사람 마우스가 있어야 보이기 때문에, 발표 때 창 2개(또는 영상)로 보여 준다.

### 4-3. AI 자동 분류 · 추천 (FR-19~22)
카드 상세에서 "AI 추천 받기"를 누르면 AI가 제목·설명을 보고 **카테고리·우선순위·담당자**를 추천해 준다. 아래는 실제 AI가 답한 화면이다(`Bug · high · 확신도 100% · 담당자 관리자`). 사용자가 추천을 받아들이거나 거절한 내용은 다음 추천에 참고된다. AI 회사를 바꿔 끼울 수 있게(Strategy 패턴) 코드를 짰다.

![AI 추천](../screenshots/03-ai-recommend.png)

- 코드: `src/shared/api/llm/index.ts`, `src/shared/lib/ai-classify-logic.ts`

### 4-4. GitHub 연동 (FR-14~18)
보드에 저장소를 연결하면 PR·이슈가 카드와 연결된다. PR이 열리거나 머지되면 웹훅(서명 확인 포함)이 카드를 정해진 칸으로 옮긴다. 커밋 메시지에 `TF-123`처럼 쓰면 그 카드와 연결된다. 같은 이벤트가 두 번 와도 한 번만 처리한다.

- 코드: `src/app/api/webhooks/github/route.ts`, `src/shared/lib/github-signature.ts`

### 4-5. AI 회의록 (FR-23~25)
회의를 음성(실시간 받아쓰기)이나 텍스트로 넣으면 AI가 **요약·참석자·안건·논의 내용**을 정리하고 **할 일**을 뽑아 준다. 뽑힌 할 일은 "카드로 보내기"로 보드에 바로 추가된다.

![회의록 요약](../screenshots/05-meeting-summary.png)

![추출된 작업](../screenshots/06-meeting-tasks.png)

- 코드: `src/shared/api/llm/index.ts`, `src/features/meeting-record/ui/upload-form.tsx`, `src/features/meeting-to-cards`

### 4-6. 권한 · 멤버 관리 (FR-27)
관리자는 가입한 사람을 이메일로 초대하고, 역할(관리자/편집자/뷰어)을 바꾸거나 내보낼 수 있다. 권한은 데이터베이스 단계(RLS)에서 막기 때문에 화면을 우회해도 소용없다.

![멤버 관리](../screenshots/07-members.png)

- 코드: `supabase/migrations/0002_rls.sql`, `supabase/migrations/0008_member_management.sql`, `features/member-manage`

## 5. 구조와 디자인 패턴

### 구조
```
브라우저  ↔  Next.js 14  ↔  Supabase(DB·로그인·실시간)
                              ↘ GitHub Webhook   ↘ AI(LLM·음성)
```
Supabase 같은 BaaS를 써서 백엔드 만드는 시간을 줄였고, 권한은 데이터베이스에서 한 번에 관리했다. 폴더는 Feature-Sliced Design으로 나눠서 찾기 쉽게 했다.

### 디자인 패턴 (설계 때 발표한 4개를 실제로 적용)

| 패턴 | 어디에 썼나 | 파일 |
|---|---|---|
| Observer | 실시간으로 보드 변경 알림 | `entities/board/model/use-board-realtime.ts` |
| Memento | 드래그 되돌리기(상태 저장·복원) | `entities/board/model/store.ts` |
| Strategy | AI 회사 바꿔 끼우기 | `shared/api/llm/index.ts` |
| Repository | 데이터 접근 한 곳에 모으기 | `entities/*/api` |
