## 2. 시스템 개요

### 2.1 목적

여러 명이 하나의 칸반 보드를 **동시에** 편집하면서 작업을 관리하고, 반복 작업(분류·회의 정리·
GitHub 상태 추적)을 AI와 자동화로 줄이는 협업 도구를 제공한다.

### 2.2 범위

- 칸반 보드/컬럼/카드 관리 및 드래그 앤 드롭
- 다중 사용자 실시간 동기화 및 충돌 처리
- GitHub 저장소 연동(PR·이슈·커밋 → 카드)
- AI 카드 분류·추천 및 AI 회의록(요약·할 일 추출)
- 워크스페이스 멤버 초대 및 역할별 권한

### 2.3 사용자 역할

| 역할 | 권한 요약 |
| --- | --- |
| Owner | 워크스페이스 소유자. 모든 권한 + 멤버/역할 관리, 마지막 owner 강등 불가 |
| Admin | 멤버 초대·역할 변경, 보드/카드 전체 편집 |
| Member | 보드/카드 생성·편집, 활동 기록 |
| (Guest) | 읽기 위주 — 쓰기 정책에서 제외 |

### 2.4 기술 환경 (제약)

- 프론트엔드: Next.js 14(App Router), TypeScript(strict), shadcn/UI
- 백엔드: Supabase(PostgreSQL · Auth · Realtime · Storage)
- 아키텍처: Feature-Sliced Design(ESLint 경계 강제)
- 외부 연동: GitHub Webhook, LLM(분류·요약), STT(음성→텍스트)

## 3. 기능 요구사항 (FR)

### 3.1 칸반 보드 코어 (FR-01 ~ FR-09)

| ID | 요구사항 | 우선순위 | 인수 기준 | 상태 |
| --- | --- | --- | --- | --- |
| FR-01 | 보드 생성·이름변경·삭제 | 必 | 보드 CRUD가 동작하고 삭제 시 하위 컬럼/카드가 함께 제거된다 | ✅ |
| FR-02 | 컬럼 추가·수정·삭제·순서변경 | 必 | 컬럼 CRUD 동작, 순서변경 가능 | 🟡 |
| FR-03 | 카드 생성(제목·설명·담당자·마감일·우선순위) | 必 | 필수/선택 필드로 카드 생성된다 | ✅ |
| FR-04 | 카드 수정·삭제 | 必 | 카드 내용 수정·삭제가 반영된다 | ✅ |
| FR-05 | 드래그 앤 드롭으로 카드 이동 | 必 | 컬럼 내/간 이동이 위치까지 정확히 저장된다 | ✅ |
| FR-06 | 필터·검색(담당자·우선순위·마감일) | 中 | 조건 조합(AND)으로 카드가 걸러진다 | ✅ |
| FR-07 | 레이블 붙이기·떼기 | 中 | 카드에 레이블을 부여/해제할 수 있다 | ✅ |
| FR-08 | 댓글 작성·수정·삭제 | 中 | 본인 댓글만 수정·삭제 가능 | ✅ |
| FR-09 | 활동 이력 자동 기록 | 中 | 카드 생성·이동 등이 활동 피드에 남는다 | ✅ |

**FR-02 부분 구현 사유**: 컬럼 추가·수정·삭제·이름변경은 동작하며 순서변경 서버 액션
(`reorderColumn`)·정렬 값도 구현되어 있으나, 컬럼을 드래그하는 화면 연결은 카드 드래그와 겹치는
처리가 남아 미완이다.

| ID | 요구사항 | 우선순위 | 인수 기준 | 상태 |
| --- | --- | --- | --- | --- |
| FR-26 | 회원가입/로그인(이메일·OAuth) | 必 | 이메일 가입·로그인, Google/GitHub 로그인 | 🟡 |
| FR-27 | 역할별 권한(관리자/편집자/뷰어) | 必 | 역할에 따라 가능한 동작이 제한된다(DB 단계 강제) | ✅ |

**FR-26 부분 구현 사유**: 이메일 로그인은 완전 동작하고 OAuth 버튼·코드도 구현되어 있으나,
로컬 환경 주소(Redirect URL)를 Google/GitHub 콘솔에 등록하지 않아 데모에서는 이메일 로그인을
사용한다. 주소만 등록하면 즉시 동작한다.

### 3.7 명세 외 추가 구현

요구사항에 없었으나 완성도를 위해 추가한 기능: 실시간 회의 음성 받아쓰기 및 화자 구분,
회의록 삭제, 시연용 자동 입력("시안") 버튼.

## 5. 제약사항 및 가정

- **C-1** 백엔드는 Supabase(BaaS)에 의존한다. 인증·실시간·스토리지·RLS는 Supabase 기능을 사용한다.
- **C-2** AI 분류·회의 요약은 LLM 키, 음성 파일 받아쓰기는 STT 키가 필요하다. 키 미설정 시 해당
  기능만 비활성화되고 앱 부팅은 유지된다(graceful degradation).
- **C-3** 실시간 받아쓰기는 브라우저 Web Speech API에 의존하므로 지원 브라우저(Chrome 등)에서만 동작한다.
- **A-1** 멤버 초대는 이미 가입한 사용자(user_profiles 존재)를 이메일로 초대하는 흐름을 가정한다.
- **A-2** 평가·시연은 로컬(`localhost:3000`) 환경에서 수행한다.

| --- | --- | --- | --- | --- |
| 기능 요구사항 (FR-01~27) | 27 | 25 | 2 | 0 |
| 비기능 요구사항 (NFR-01~19) | 19 | 6 | 11 | 2 |

기능 요구사항은 핵심 4축(실시간 협업·GitHub 연동·AI 분류·AI 회의록)을 포함해 사실상 전부

보안과 유지보수 구조를 충족했으며, 운영 서버·자동 백업·정량 측정은 과제 범위를 벗어나 후속으로 둔다.
