## 0. 사전 준비 (시연 시작 전)

```bash
cd ~/development/PROJECT/kanban-collab

# 1) 앱 + AI + 절전방지 (한 번에)
./demo-start.command          # localhost:3000, Ollama(qwen2.5:3b), caffeinate

# 2) GitHub 라이브(5막) 쓸 때만 — 터널 + 웹훅 자동 연결
./demo-tunnel.command
```

- **Chrome 필수** (음성인식 Web Speech API). Safari 불가.
- 첫 "회의 시작" 시 **마이크 권한 1회 허용**.
- 실시간 협업(4막)용 **시크릿 창** 미리 열어두기.
- ⚠️ **인터넷 필요**: 백엔드(Supabase)는 클라우드라 로그인·보드·실시간·회의저장·GitHub 웹훅 전부 온라인. (로컬은 AI 추론 Ollama 뿐)

### 로그인 계정 (데모 워크스페이스, 미리 세팅됨)

| 계정 | 비밀번호 | 역할 | 용도 |
|---|---|---|---|
| `admin@admin.com` | `admin` | admin | **메인 시연 로그인** |
| `claude-test@local.test` | `ClaudeTest1234!` | admin | 실시간 협업 2번째 창 |
| `demo@taskflow.dev` | (원래 비번) | owner | 최고 권한 |

- 로그인은 이메일/비밀번호. (Google/GitHub OAuth 버튼은 있으나 localhost 리다이렉트 미설정)
- 데모 보드: "데모 워크스페이스 → 스프린트 보드" (카드: 로그인 버그 수정, API 연동 작업 / 컬럼: To Do·In Progress·Done)
- 입력 폼마다 **✨ 시안 버튼** — 클릭 한 번으로 샘플 채움(회의록·카드추가·저장소링크·멤버초대).

## 1. 시연 순서 (스토리 흐름)

"개발팀이 한 스프린트를 관리한다"는 흐름. 각 단계에 **동작 / 요구사항(FR) / 멘트**.

### 0막 — 로그인 (30초)
| 동작 | FR | 멘트 |
|---|---|---|
| admin@admin.com / admin → 워크스페이스 → 스프린트 보드 | FR-26 | "팀별 워크스페이스 안에 칸반 보드. 역할(owner/admin/member)별 권한이 다릅니다." |

### 1막 — 칸반 기본
| 동작 | FR | 멘트 |
|---|---|---|
| 카드 추가(✨시안) → 제목·우선순위·마감일 | FR-03 | "할 일을 카드로. 생성 시 우선순위·마감일까지 한 번에." |
| 카드 드래그로 컬럼 이동 | FR-05 | "진행 상황은 끌어다 놓기로. 위치 즉시 저장." |
| 컬럼 추가 / 이름 변경 | FR-02 | "팀 워크플로우에 맞게 컬럼을 자유롭게." |
| 상단 검색/필터(우선순위·담당자·마감일) | FR-06 | "카드가 많아도 바로 필터." |

### 2막 — AI 태스크 자동 분류 ⭐
| 동작 | FR | 멘트 |
|---|---|---|
| 카드 열기 → "AI 추천 받기" → 카테고리·우선순위·담당자 추천 → 적용 | FR-19·20·21·22 | "내용만 보고 **로컬 AI가 분류·우선순위·담당자까지 제안**. 마감 임박 시 우선순위 자동 상향." |

> 핵심: 수동 분류 노동을 AI가 대신. 로컬 Ollama(qwen2.5:3b)라 인터넷 없이 추론.

### 3막 — 카드 상세 협업
| 동작 | FR | 멘트 |
|---|---|---|
| 레이블 · 마감일 캘린더 · 댓글 작성/수정 | FR-04·07·08 | "카드 안에서 레이블·댓글로 협업. 댓글은 본인 것만 수정/삭제." |

### 4막 — 실시간 협업 ⭐
| 동작 | FR | 멘트 |
|---|---|---|
| 시크릿 창(claude-test)으로 같은 보드 → 한 창에서 카드 이동 → 다른 창 즉시 반영 + 접속자 표시 | FR-10·11·12·13 | "여러 명 동시 작업해도 **실시간 동기화**. 같은 카드 동시 편집 시 충돌도 감지." |

> Supabase Realtime (CDC + Presence + Broadcast). NFR-03 "200ms 이내" 컨셉.

### 5막 — GitHub PR 자동화 ⭐ (라이브)
| 동작 | FR | 멘트 |
|---|---|---|
| 좌측 PR 자동화 패널 설명 → **GitHub에서 PR 머지** → 보드의 "API 연동 작업" 카드가 **Done으로 자동 이동 + 활동 피드 🤖 로그** | FR-14·15·16·17·18 | "PR을 머지하는 순간 카드가 자동 완료. 이슈는 카드로 자동 생성, 커밋도 태스크에 연결." |

> 실제 GitHub repo(`taskflow-webhook-demo`) + cloudflared 터널로 localhost를 공개 → 진짜 웹훅이 들어와 카드 이동. **라이브 검증 완료.**
> 백업: `./demo-webhook.command merged` (터널·인터넷 없이 로컬에서 서명된 웹훅 전송, 동일 결과).

### 6막 — AI 회의록 → 태스크 ⭐
| 동작 | FR | 멘트 |
|---|---|---|
| 회의록 → **실시간 회의**(참가자 등록 → 회의 시작 → 말하기, 발언자 클릭 → `[이름]` 화자 태그) 또는 ✨시안/텍스트 → 생성 → **요약·작업 추출** → 화자별 회의록 + 할 일 → 카드로 보내기 | FR-23·24·25 | "회의 메모·음성을 **AI가 구조화 회의록 + 담당자별 할 일**로 정리해 칸반 카드까지." |

> 받아쓰기 = 브라우저 Web Speech API(온라인), 정리·할 일 추출 = 로컬 LLM(오프라인). 자동 음성 화자분리는 아니고 **참가자 등록 + 발언자 태그** 방식.

### 7막 — 팀/권한 + 활동이력 (마무리)
| 동작 | FR | 멘트 |
|---|---|---|
| 워크스페이스 멤버 역할 변경 + 멤버 초대(✨시안) | FR-26·27 | "관리자가 이메일로 팀원 초대, 역할별 권한." |
| 좌측 활동 피드 | FR-09 | "모든 변경은 자동 기록." |

> 멤버 초대/역할변경/제거는 검증 실패 시 토스트로 안내(미가입·이미 멤버·마지막 소유자 등). 가입된 비멤버 이메일을 넣어야 실제 추가됨.

## 2. 강조 포인트 — "Trello와 뭐가 다른가" 4가지

1. **AI 태스크 자동 분류** (FR-19~22)
2. **AI 회의록 → 태스크 변환** (FR-23~25)
3. **실시간 협업** (FR-10~13)
4. **GitHub PR 자동화** (FR-14~18) — 라이브 실연

> 시간 부족하면: 1막 압축 → 2·6막(AI)·4막(실시간)·5막(GitHub)에 집중.

## 3. GitHub 라이브 시연 구성 (5막)

- **임시 repo**: `sanghyeonKim0201/taskflow-webhook-demo` (시연용)
- **데모 보드** ↔ repo 연결, PR 자동화 매핑(PR 머지 → Done 컬럼)
- **카드 "API 연동 작업"** ↔ 데모 PR 연결 (머지 시 이 카드 이동)
- **터널**: `demo-tunnel.command` — cloudflared로 localhost:3000 공개 + GitHub 웹훅 URL 자동 갱신(터널 주소가 매번 바뀌므로)
- **웹훅**: 서명검증(HMAC-SHA256) + delivery 멱등키, service_role로 카드 이동
- **시연 절차**: demo-start → demo-tunnel → 보드 띄움 → GitHub PR "Merge" 클릭 → 보드 자동 이동 확인
- **백업**: `./demo-webhook.command merged` (오프라인 로컬 시뮬레이션, 동일 결과)
- **정리(시연 후)**: 터널 Ctrl+C · `gh repo delete` · service_role/PAT 폐기

## 4. 요구사항 충족 표

**기능 요구사항 FR-01 ~ FR-27: 27개 전부 구현 ✅**

| 그룹 | FR | 비고 |
|---|---|---|
| 칸반 | FR-01~09 | 보드/컬럼/카드 CRUD, 드래그(LexoRank), 필터·검색, 레이블, 댓글, 활동이력 |
| 실시간 | FR-10~13 | CDC·Presence·Broadcast·충돌감지(updated_at) |
| GitHub | FR-14~18 | 연결·커밋·PR 자동이동·이슈→카드·커밋연결 (라이브) |
| AI 분류 | FR-19~22 | 카테고리·우선순위·담당자·few-shot, 마감 결정적 후처리 |
| 회의록 | FR-23~25 | 구조화 생성·태스크 추출·검토 후 카드화 + 실시간 음성/화자 태그 |
| 인증/권한 | FR-26~27 | 이메일·OAuth, 역할별 권한 + 멤버 초대 |

**비기능(NFR): 보안·구조는 충족, 측정·운영 항목은 미검증 (정직하게)**

- ✅ NFR-08 JWT · NFR-09 bcrypt(Supabase) · NFR-10 웹훅 서명검증 · NFR-15 FSD
- ⚠️ NFR-16 테스트 커버리지(vitest 단위 테스트 있으나 커버리지 수치 미설정) · NFR-01~06 성능 수치(미실측) · NFR-13 반응형 · NFR-17 브라우저호환 · NFR-11/12 가용성 · NFR-19 백업

## 5. 예상 질문 Q&A

| 질문 | 답변 |
|---|---|
| AI 모델? | 로컬 Ollama(qwen2.5:3b) — 오프라인·무료. `LLM_BASE_URL`만 바꿔 OpenAI/Groq/Gemini로 스왑(Strategy/Adapter 추상화). |
| 실시간 어떻게? | Supabase Realtime — CDC(postgres_changes) + Presence + Broadcast. 카드 변경은 250ms 디바운스 후 재동기화. |
| GitHub 자동화 진짜 되나? | 네, 라이브. 임시 repo + cloudflared 터널로 실제 PR 머지 웹훅이 카드를 옮김. HMAC 서명검증 + delivery 멱등키. |
| 정렬/드래그? | LexoRank 문자열, 인접 사이값만 계산 O(1). |
| 동시 편집 충돌? | updated_at 비교로 감지 후 낙관적 롤백(FR-13). |
| 화자 구분? | 자동 음성분리는 아님 — 참가자 등록 후 발언자 태그(`[이름]`)로 AI가 화자별 정리. |
| 테스트? | vitest 단위 테스트(LexoRank·충돌감지 등). 커버리지 수치 측정은 안 함(정직하게). |
| 성능/확장성? | 학교 과제라 대규모 트래픽 미고려. 실시간 200ms 컨셉, 실측 벤치 미수행. |
| 아키텍처? | FSD(Feature-Sliced Design) — app/processes/widgets/features/entities/shared, ESLint 경계 강제. Next.js 14 App Router + Supabase. |
| 데이터 안전? | RLS로 워크스페이스 멤버만 접근, 역할별 쓰기 분리. service_role은 웹훅 등 서버 전용. |
| 디자인 패턴? | Strategy(LLM provider) · Adapter(OpenAI 호환 엔드포인트) · Observer(Realtime 구독). |

## 6. 동선 요약 (한 장)

```
[사전] demo-start.command + demo-tunnel.command, Chrome, 시크릿 창
로그인(admin/admin) → 스프린트 보드
  → [1막] 카드추가(✨)·드래그·필터
  → [2막] ⭐ AI 추천(분류·우선순위·담당자)
  → [3막] 카드 상세(레이블·댓글·마감일)
  → [4막] ⭐ 실시간 협업 (시크릿 창)
  → [5막] ⭐ GitHub PR 머지 → 카드 자동 Done (라이브)
  → [6막] ⭐ AI 회의록 → 태스크 (실시간 음성/화자 태그)
  → [7막] 멤버·권한·활동이력 (마무리)
[정리] 터널 종료 · 임시 repo·키 폐기
```

시간 빠듯하면: 1막 압축 → 2·6막(AI)·4막(실시간)·5막(GitHub)에 집중.
