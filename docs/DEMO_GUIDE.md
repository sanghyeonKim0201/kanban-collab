# TaskFlow 시연 가이드

> 대학 발표(교수님 컴퓨터에서 브라우저로 접속)용 시연 시나리오·흐름·강조점.
> 목표: 약 10분, "그냥 Trello"가 아니라 **AI + 실시간 + GitHub 자동화**가 붙은 칸반임을 각인.

---

## 0. 사전 준비 (시연 시작 전, 내 노트북)

강의실에 노트북을 가져가 켜두고, 교수님 컴퓨터에서는 **터널 URL을 브라우저로** 연다.

```bash
# (1) 절전 방지 — 시연 내내 깨어있게
caffeinate -d            # 터미널 1 (맥)

# (2) 로컬 AI
ollama serve             # 터미널 2 (이미 떠있으면 생략). 모델: qwen2.5:3b

# (3) 앱 프로덕션 구동 (메인 레포에서!)
cd ~/development/PROJECT/kanban-collab
pnpm build && pnpm start # 터미널 3 → http://localhost:3000

# (4) 공개 터널 (교수님이 열 URL)
cloudflared tunnel --url http://localhost:3000   # 터미널 4
#   → https://xxxx.trycloudflare.com  (이 URL 사용, 재시작 금지)
```

**로그인 계정 (데모 워크스페이스 멤버 3명, 미리 세팅됨)**

| 계정 | 비밀번호 | 역할 | 용도 |
|---|---|---|---|
| `claude-test@local.test` | `ClaudeTest1234!` | admin | **메인 시연 로그인** |
| `admin@admin.com` | (본인 계정 비번) | member | 실시간 협업 2번째 창 |
| `demo@taskflow.dev` | (원래 비번) | owner | 최고 권한 |

- 로그인은 **이메일/비밀번호**로 (터널 URL이라 구글/깃헙 OAuth는 미설정).
- 실시간 협업 시연하려면 **창 2개**(또는 노트북+폰) 미리 준비.
- 데모 보드: "데모 워크스페이스 → 스프린트 보드" (카드 2개: 로그인 버그 수정, API 연동 작업).

## 1. 시연 순서 (스토리 흐름)

"개발팀이 한 스프린트를 관리한다"는 흐름으로. 각 단계에 **무엇을 보여주고(동작)**, **무슨 요구사항(FR)**인지, **멘트**를 적었다.

### 1막 — 칸반 기본 (작업 관리)

| # | 동작 | 요구사항 | 멘트 |
|---|---|---|---|
| 1 | 로그인 → 워크스페이스 → "스프린트 보드" 진입 | FR-26 | "이메일 로그인. 팀별 워크스페이스 안에 칸반 보드가 있습니다." |
| 2 | "카드 추가" → 상세 옵션 펼쳐 제목·설명·우선순위·마감일 입력 | FR-03 | "할 일을 카드로. 생성 시 우선순위·마감일까지 한 번에." |
| 3 | 카드를 다른 컬럼으로 **드래그** | FR-05 | "진행 상황은 끌어다 놓기로. 위치는 즉시 저장됩니다." |
| 4 | "컬럼 추가" / 컬럼 이름 더블클릭 변경 | FR-02 | "팀 워크플로우에 맞게 컬럼을 자유롭게." |
| 5 | 상단 **검색/필터**(우선순위·담당자·마감일) | FR-06 | "카드가 많아도 담당자·우선순위·마감일로 바로 필터." |

### 2막 — AI 태스크 자동 분류 ⭐ (강조 1)

| # | 동작 | 요구사항 | 멘트 |
|---|---|---|---|
| 6 | 카드 열기 → **"AI 추천 받기"** → 카테고리·우선순위·**담당자** 추천 → "적용" | FR-19·20·21·22 | "태스크 내용만 보고 **AI가 분류·우선순위·담당자까지 제안**합니다. 마감일이 임박하면 우선순위도 올려주고요." |

> 핵심 한 줄: "수동 분류 노동을 AI가 대신." (로컬 Ollama라 인터넷 없이도 동작)

### 3막 — 카드 상세 협업

| # | 동작 | 요구사항 | 멘트 |
|---|---|---|---|
| 7 | 카드 상세: **레이블** 붙이기, **마감일 캘린더**, **댓글** 작성/수정 | FR-04·07·08 | "레이블·댓글·마감일로 카드 안에서 협업. 댓글은 본인 것만 수정/삭제." |

### 4막 — 실시간 협업 ⭐ (강조 2)

| # | 동작 | 요구사항 | 멘트 |
|---|---|---|---|
| 8 | **두 번째 창**(admin@admin.com)으로 같은 보드 열기 → 한 창에서 카드 이동 → **다른 창에 즉시 반영** + 접속자 표시 | FR-10·11·12·13 | "팀원이 동시에 작업해도 **실시간 동기화**. 같은 카드를 동시에 건드리면 충돌도 감지합니다." |

> Supabase Realtime(WebSocket). 명세 NFR-03 "200ms 이내 반영" 컨셉.

### 5막 — GitHub 연동 ⭐ (강조 3)

| # | 동작 | 요구사항 | 멘트 |
|---|---|---|---|
| 9 | 좌측 **PR 자동화 패널** 설명(PR 열림→진행, 머지→완료 매핑) + 활동 피드의 자동화 로그 | FR-14·15·16·17·18 | "GitHub 저장소를 연결하면 **PR을 머지하는 순간 카드가 자동으로 '완료'로 이동**. 커밋 메시지에 `TF-123` 쓰면 태스크 자동 연결, 이슈는 카드로 자동 생성." |

> 라이브 웹훅은 배포+시크릿이 필요. **데모는 설정 패널 + 동작 설명**으로 진행하고, "구현은 완료, 배포 시 동작"이라고 안내. (자동화 로그가 활동 피드에 쌓이는 화면을 같이 보여주면 설득력 ↑)

### 6막 — AI 회의록 → 태스크 ⭐ (강조 4)

| # | 동작 | 요구사항 | 멘트 |
|---|---|---|---|
| 10 | 좌측 **회의록** → 회의 내용 **텍스트 붙여넣기** → AI가 **참석자/안건/결정사항** 정리 + **할 일 추출** → 검토·수정 → **보드에 카드로 추가** | FR-23·24·25 | "회의 끝나고 메모만 붙여넣으면 **AI가 회의록을 정리하고 할 일을 뽑아 칸반 카드로**. 추가 전에 검토·수정도 가능." |

> 오디오 업로드(STT)는 키 필요 → **텍스트 붙여넣기**로 시연.

### 7막 — 팀/권한 관리 (마무리)

| # | 동작 | 요구사항 | 멘트 |
|---|---|---|---|
| 11 | 워크스페이스 상세: 멤버 목록(owner/admin/member 역할) + **멤버 초대**(이메일) | FR-26·27 | "관리자는 이메일로 팀원 초대, 역할별 권한(편집자/뷰어)이 다릅니다." |
| 12 | 보드 좌측 **활동 피드** 가리키기 | FR-09 | "모든 변경은 자동으로 기록됩니다." |

## 2. 강조 포인트 — "Trello와 뭐가 다른가" 4가지

발표에서 이 4개만 확실히 각인시키면 됨:

1. **AI 태스크 자동 분류** (FR-19~22) — 내용 보고 카테고리·우선순위·담당자 제안.
2. **AI 회의록 → 태스크 변환** (FR-23~25) — 회의 메모 → 구조화 회의록 + 자동 할 일.
3. **실시간 협업** (FR-10~13) — 다중 사용자 동시 편집·동기화·충돌 감지.
4. **GitHub PR 자동화** (FR-14~18) — PR/커밋/이슈가 보드에 자동 반영.

> 1·2번(AI)이 제일 임팩트 큼 → 시간 부족하면 1막은 빠르게, 2·6막에 시간 배분.

## 3. 요구사항 충족 표 (교수님 대비)

**기능 요구사항 FR-01 ~ FR-27: 27개 전부 구현 ✅**

| 그룹 | FR | 비고 |
|---|---|---|
| 칸반 | FR-01~09 | 보드/컬럼/카드 CRUD, 드래그, 필터·검색, 레이블, 댓글, 활동이력 |
| 실시간 | FR-10~13 | 커서·동기화·접속자·충돌 (Supabase Realtime) |
| GitHub | FR-14~18 | 연결·커밋·PR 자동이동·이슈→카드·커밋연결(#CARD/TF-) |
| AI 분류 | FR-19~22 | 카테고리·우선순위·담당자·피드백(few-shot) |
| 회의록 | FR-23~25 | 구조화 생성·태스크 추출·검토 후 카드화 |
| 인증/권한 | FR-26~27 | 이메일·OAuth, 역할별 권한 + 멤버 초대 |

**비기능 요구사항(NFR): 보안·구조는 충족, 측정·운영 항목은 미검증 (정직하게)**

- ✅ NFR-08 JWT · NFR-09 bcrypt(Supabase) · NFR-10 웹훅 서명검증 · NFR-15 FSD 아키텍처
- ⚠️ NFR-16 테스트 커버리지 70%(단위 테스트 162개 있으나 커버리지 수치 측정은 미설정) · NFR-01~06 성능 수치(미실측) · NFR-13 반응형 · NFR-17 브라우저 호환 · NFR-11/12 가용성 · NFR-19 백업

## 4. 예상 질문 Q&A 대비

| 질문 | 답변 |
|---|---|
| "AI는 어떤 모델?" | 로컬 **Ollama(qwen2.5:3b)** — 오프라인·무료. API 키만 넣으면 OpenAI/Groq 같은 클라우드 LLM으로도 동작하게 추상화돼 있음. |
| "GitHub 자동화 진짜 되나?" | 구현 완료. 라이브는 웹훅 시크릿+배포가 필요해 데모는 설정·로그로 보여줌. 코드는 서명검증·멱등키·동시성까지 처리. |
| "테스트는?" | 단위 테스트 **162개**(핵심 로직·순수 함수 중심). 커버리지 **수치 측정 설정은 안 했다**고 정직하게. |
| "성능/확장성은?" | 명세 2.4대로 **학교 과제라 대규모 트래픽 미고려**. 실시간은 200ms 컨셉, 실측 벤치는 안 함. |
| "아키텍처?" | **FSD(Feature-Sliced Design)** — entities/features/widgets/app 레이어. Next.js 14 App Router + Supabase(Auth·DB·Realtime). |
| "데이터는 안전한가?" | RLS(Row Level Security)로 워크스페이스 멤버만 접근, 역할별 쓰기 권한 분리. 웹훅은 service_role로 격리. |

## 5. 동선 요약 (한 장)

```
로그인 → 보드 진입
  → [1막] 카드 추가·드래그·컬럼·필터
  → [2막] ⭐ AI 추천(분류·우선순위·담당자)
  → [3막] 카드 상세(레이블·댓글·마감일)
  → [4막] ⭐ 실시간 협업 (창 2개)
  → [5막] ⭐ GitHub PR 자동화 (패널+설명)
  → [6막] ⭐ AI 회의록 → 태스크
  → [7막] 멤버·권한·활동이력 (마무리)
```

시간이 빠듯하면: 1막 압축 → 2막·6막(AI)·4막(실시간)에 집중.
